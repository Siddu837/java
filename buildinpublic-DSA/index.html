📦
Inbuilt Methods
java.lang
Java's standard library provides ready-to-use methods. No need to write them — just call and use!
// Math methods Math.pow(2, 10); // → 1024.0 Math.sqrt(144); // → 12.0 Math.abs(-99); // → 99 Math.max(5, 10); // → 10 Math.min(5, 10); // → 5 // String methods "hello".toUpperCase(); // → "HELLO" "Java".length(); // → 4 "hi".charAt(0); // → 'h'
🛠
User-Defined Methods
custom
Write logic once, reuse it everywhere. Makes code cleaner, modular, and easier to debug.
// Return type method static int add(int a, int b) { return a + b; } // Void method (no return) static void greet(String name) { System.out.println("Hey, " + name + "!"); } // Calling inside main() int sum = add(5, 3); // → 8 greet("Siddu"); // Hey, Siddu!
🔢
Overloading — Parameters
compile-time
Same method name, different number of parameters. Java picks the right one at compile time.
// Different number of params static int add(int a, int b) { return a + b; } static int add(int a, int b, int c) { return a + b + c; } add(3, 4); // → 7 (2-param version) add(1, 2, 3); // → 6 (3-param version)
🔄
Overloading — Data Types
polymorphism
Same method name, different parameter types. Java resolves which version to call based on the argument type.
// Different data types static void display(int x) { System.out.println("int: " + x); } static void display(double x) { System.out.println("double: " + x); } static void display(String x) { System.out.println("String: " + x); } display(42); // → int: 42 display(3.14); // → double: 3.14 display("hi"); // → String: hi
🔒
Method Scope
scope
Variables declared inside a method only live within that method. Other methods cannot see them.
static void methodA() { int x = 10; // lives only in methodA System.out.println(x); // ✅ works } static void methodB() { // System.out.println(x); ❌ error! // x is NOT visible here int x = 99; // this is a DIFFERENT x System.out.println(x); // ✅ 99 }
📦
Block Scope
scope
Variables declared inside a {} block only exist within that block — even inside the same method.
static void demo() { int x = 10; // method scope if (true) { int y = 20; // block scope System.out.println(x + y); // ✅ 30 } // System.out.println(y); ❌ // y is out of scope here! for (int i = 0; i < 3; i++) { // i only lives inside this loop } // System.out.println(i); ❌ }

Why Patterns?

Loop Mastery

Patterns train your brain to think in nested loops. Every pattern is rows × columns. Once you see that, any pattern becomes solvable using a simple formula.

Why Functions?

DRY Principle

Don't Repeat Yourself. Functions let you write logic once and call it anywhere. Overloading adds flexibility — same name, smarter behavior based on input.

Key Insight

Scope = Memory Safety

Understanding scope prevents hard-to-find bugs. Variables only live in their block — this forces cleaner, more predictable and readable code.

What's Next?

Arrays & Searching

Next: arrays, linear search, binary search, and bubble sort. The nested-loop intuition from patterns maps directly to array traversal algorithms.

📐
The Universal Pattern Formula
key insight
Every pattern you'll ever write follows this skeleton. Only the inner condition changes — master that, master all patterns:
for (int i = 1; i <= n; i++) { // outer loop = rows for (int j = 1; j <= ???; j++) { // inner loop = cols (this changes!) System.out.print("* "); // what to print } System.out.println(); // newline after each row } // Swap the inner condition: // Half pyramid → j <= i // Inverted → j <= (n - i + 1) // Floyd's → print count++ instead of * // Hollow rect → i==1 || i==n || j==1 || j==n // Diamond → spaces + stars formula per row // Binary pyramid → print (i+j)%2 per cell
